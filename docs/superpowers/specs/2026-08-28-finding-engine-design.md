# 커밋 발견 엔진 (Finding Engine) — 오버레이 알약 재정의

## 배경

지금까지 데스크톱 오버레이의 접힌 알약은 "적재선"(우당탕 세 개의 SVG 게이트가 기준선 아래로 가라앉는 시각화)으로 커밋 안 한 파일/push 대기/글 안 쓴 커밋 세 수치를 형태로 보여줬다. 세션 중 `frontend-design` 스킬로 다시 검토한 결과와, 사용자가 Claude Design으로 직접 그린 목업(레포 루트 `Week Review UI.html`, 섹션 "3b 오버레이 · 상태 말고 다음 할 일")을 근거로 이 방식을 폐기하기로 했다: 세 수치를 형태로 압축해도 "그래서 뭘 하지"가 안 나온다는 게 핵심 문제였다.

3b가 제안한 대안: 알약은 개수를 보여주는 대신 **지금 걸리는 것 하나를 문장으로** 말한다("IPC 크기 검증 확인해볼 것", "backend·desktop이 같이 바뀜", "글감 4개 쌓임", "다 내보냈어요"). 누르면 팝오버에 근거가 나온다.

같은 목업의 "3a 주간 리뷰" 섹션은 웹 대시보드에 커밋별 발견 목록 + "지금 만지는 중" 구조 제안 + "계속 걸리는 것" 반복 습관 카운터를 보여주는 새 페이지를 제안한다. 이번 스펙은 3b(오버레이)와 3a(웹 대시보드)를 같이 다룬다 — 둘 다 같은 분석 엔진 위에서 돈다.

**전제**: 이 프로젝트의 AI 생성 경로(Gemini API)는 현재 막혀 있다(구글 쪽 403, 클라이언트에서 해결 불가). 따라서 이번 v1의 발견 엔진은 **LLM 없이 순수 휴리스틱/패턴 매칭만**으로 돈다. "IPC 크기 검증 빠짐" 같은 문구는 실제로 코드를 의미적으로 이해해서 나오는 게 아니라, 미리 정해둔 패턴에 걸렸을 때 나오는 정형 문구다 — 오탐/누락을 인정하고 간다.

## 목표

- 오버레이 알약이 "지금 가장 급한 것 하나"를 문장으로 보여준다.
- 웹 대시보드에 주간 리뷰 페이지(커밋별 발견, 반복 습관 카운터)를 추가한다.
- 발견은 등급(보안·버그 가능성 > 구조 > 백로그)으로 우선순위가 매겨진다.

## 비목표 (v1에 안 넣는 것)

- LLM 기반 의미 분석 (Gemini 복구 후 별도 스펙).
- git commit/커밋 분할을 백엔드가 대신 실행하는 것. 팝오버는 **추천 명령어를 보여주고 클립보드로 복사**만 한다 — 실제 `git add`/`git commit`은 사용자가 터미널에서 직접 친다. 이유: pre-commit hook 실패, GPG 서명 누락, `.git/index.lock` 충돌 같은 상황을 백엔드가 대신 만나면 로컬 작업 트리가 꼬일 위험이 있고, 원자적 커밋 분할(스테이징 초기화 → 부분 add → 커밋 반복)을 견고하게 구현하는 것 자체가 v1 스코프를 넘어선다. 개발자가 커밋 메시지와 변경 단위의 최종 통제권을 쥐는 게 맞기도 하고.
- "돌리기"(테스트 실행) 버튼의 실제 실행 — 마찬가지로 명령어 복사까지만.
- v2로 미룬 것: 로컬 의존성 파일을 분석해서 외부 기술 트렌드(GitHub Trending/RSS)와 매칭해 추천하는 "개발자용 op.gg" 기능. 이건 로컬 git 분석이 아니라 외부 데이터 연동+매칭이 핵심이라 스코프가 완전히 다르다 — 별도 브레인스토밍/스펙으로 진행한다. (메모: GitHub Trending은 공식 API/RSS가 없음 — 개별 프레임워크의 `https://github.com/{org}/{repo}/releases.atom`이 더 안정적인 소스가 될 것.)

## 아키텍처

```
[작업 중(uncommitted) diff] --(오버레이 폴링, 8초)--> FindingEngine --(휘발성, 저장 안 함)--┐
                                                                                          ├--> GET /api/overlay/next-action --> 텍스트 알약
[커밋 감지 시 1회]         --(로컬 git/GitHub 동기화)--> FindingEngine --(finding 테이블)--┘
                                                                              |
                                                                              +--> GET /api/week (확장) --> 웹 주간 리뷰 페이지
```

- **작업 중 diff**: 규칙을 라이브로 돌리되 결과를 저장하지 않는다. 커밋하면 사라지는 게 자연스럽다.
- **커밋된 diff**: 커밋이 로컬에 처음 감지될 때 한 번만 규칙을 돌려 `finding` 테이블에 저장한다. "글에 넣었음"/"넘기기" 같은 상태를 기억해야 하고, 반복 습관 카운터("테스트 없이 커밋 9번")도 히스토리 조회가 필요해서다.

### 데이터 모델

새 테이블 `finding`:

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `commit_id` | FK, 어느 커밋에서 나온 발견인지 |
| `rule_id` | 규칙 식별자 (문자열 키) |
| `category` | 보안 / 구조 / 백로그 / 기록 |
| `message` | 알약/리스트에 보일 문구 |
| `evidence` | 근거(파일 경로, 스니펫, 커맨드 등 JSON) |
| `status` | `OPEN` / `DISMISSED` / `USED_IN_POST` |
| `created_at` | |

**유니크 제약**: `(commit_id, rule_id)` — 폴링이 여러 번 돌거나 백엔드가 재시작돼도 같은 커밋에 같은 규칙이 중복 저장되지 않는다.

규칙 계산은 기존 커밋 수집 경로(로컬 git 신규 커밋 감지/GitHub 동기화 지점)에 얹는다 — 새 커밋이 처음 저장되는 바로 그 지점에서 규칙을 돌리고 끝.

## 규칙 카탈로그 (v1)

규칙은 두 부류로 나뉜다:
- **알약 후보** — 지금 당장 뭘 하라고 말할 만한 것. 우선순위 큐에 들어감.
- **추세 전용** — 3a "계속 걸리는 것"에만 집계되고 알약엔 절대 안 뜸. 급한 게 아니라 습관 지표라서 실시간으로 띄우면 잔소리로 느껴져 앱을 끄게 만든다.

### 1등급 · 보안/버그 가능성 (알약 후보)
- `ipcMain.on`/`handle` 신규 추가 + 근처에 길이/타입 체크 없음
- CORS 와일드카드(`*`), `nodeIntegration: true`, `contextIsolation: false`
- `eval(`, 문자열 결합 `child_process.exec`, 하드코딩된 토큰/키 패턴
- 문구는 확신형이 아니라 "확인해볼 것" 톤 — 패턴 매칭의 한계를 인정한다.

### 2등급 · 구조 (알약 후보)
- **커밋 분리 제안**: 판정 조건은
  ```
  modifiedTopLevelFolders(루트 직속 파일 제외: docker-compose.yml, README.md, .gitignore 등).size >= 2
    && (totalChangedLines >= 50 || changedFileCount >= 4)
  ```
  루트 파일 제외와 크기 임계값 없이 폴더 개수만 보면, 포트 번호 하나 바꾸며 여러 폴더를 스치는 사소한 커밋까지 다 걸려서 오탐이 심해진다. `desktop/` 안에서 `main.js`+`preload.js`+렌더러 `.tsx`처럼 한 폴더 안에서 여러 파일 걸치는 건 원래 한 덩어리이므로 안 건드린다.
  - 문구는 지시형("커밋을 나누세요")이 아니라 중립형: "backend·desktop이 같이 바뀜 — 의도한 거면 넘어가도 됨". API 변경과 그걸 호출하는 클라이언트 코드처럼, 여러 영역이 함께 바뀌는 게 오히려 원자적이고 옳은 경우가 많기 때문.
  - 팝오버에는 폴더별 파일 그룹 + **추천 git 명령어 + 복사 버튼**만 보여준다(실행은 안 함, 위 "비목표" 참고).
- 200줄 넘는 커밋

### 3등급 · 백로그 (알약 후보, 기존 수치 재사용)
- push 대기 N개 / 글감 N개 쌓임 / (1·2등급에 걸릴 게 없을 때만) 커밋 안 한 파일 N개

### 추세 전용 (3a에만 집계)
- 테스트 파일 안 건드리고 소스만 바뀐 커밋 수
- 커밋 메시지 품질(짧거나 "fix"/"wip" 단독)
- diff에 `TODO` 신규 추가 횟수

## 우선순위 선택

라이브 발견 + 저장된 `OPEN` 발견 + 백로그 수치를 합쳐서, 1등급 > 2등급 > 3등급 순으로 첫 번째로 비어있지 않은 등급에서 하나를 고른다. 같은 등급 안에서는 **묵힌 기간이 긴 것 먼저**. 아무것도 없으면 "다 내보냈어요".

## API

- `GET /api/overlay/next-action` → `{ message, tier(SECURITY/STRUCTURE/BACKLOG/CLEAR), evidence, findingId, sinceMs }`. 오버레이 기존 폴링에 얹어서 같이 호출.
- `PATCH /api/findings/{id}` → `status`를 `DISMISSED`/`USED_IN_POST`로 변경 ("넘기기"/"글에 넣었음").
- `GET /api/week` 확장 → 커밋마다 `findings[]`, `recurringFriction[]`(규칙별 최근 발생 횟수) 추가.

## 프론트엔드 변화

### 데스크톱 오버레이
- `desktop/src/LoadLinePill.tsx` 삭제 — SVG 게이트 계산이 통째로 필요 없어진다.
- `OverlayWidget`은 이미 있는 `TrayIndicator`의 텍스트 알약 모드만 사용한다. 라벨은 `next-action` 응답, 점 색은 tier로 매핑(SECURITY=러스트, STRUCTURE=강청, BACKLOG=중립, CLEAR=세이지).
- 팝오버는 tier별로 다른 내용을 그린다: STRUCTURE면 파일 그룹 + 명령어 복사 버튼, SECURITY면 근거 스니펫 + "에디터에서 열기"(`vscode://file/...`)/"넘기기"/"글에 넣었음".
- `useOverlayData`의 기존 폴링에 `next-action` fetch 하나만 얹는다. 백엔드가 죽으면 기존 "연결 안 됨" 처리를 그대로 재사용 — 새 fallback을 안 만들어도 된다.

### 웹 대시보드
- `/week-review` 새 페이지 — 커밋별 findings 리스트, "지금 만지는 중" WIP 패널(구조 규칙 재사용), "계속 걸리는 것" 카운터.

## 에러 처리

- 규칙 하나가 예외를 던져도 전체 폴링이 죽지 않도록 규칙별 try/catch — 로그만 남기고 스킵.
- 라이브(작업 중) diff 크기 가드: lockfile(`package-lock.json`, `*.lock`)·빌드 산출물 경로는 규칙 평가 대상에서 아예 제외하고, 파일당 크기 상한도 둔다. 8초마다 도는 정규식 연산이 큰 생성 파일에 낭비되는 것도 막고, 압축된 벤더 번들 안에서 `eval(` 같은 패턴이 우연히 잡히는 오탐도 막는다.
- `next-action` 호출 실패는 새로 처리할 것 없이 오버레이의 기존 `connectionOk` 폴백을 그대로 탄다.
- 클립보드 복사 실패 시 명령어를 선택 가능한 텍스트로라도 보여준다.

## 테스트

- 규칙마다 유닛 테스트(매칭 케이스 + 안 걸려야 하는 케이스 하나씩) — 이 프로젝트가 `git`/`week`/`commit` 쪽에 이미 테스트를 두는 관례를 그대로 따른다.
- 우선순위 큐 선택 로직(등급 순서 + 묵힌 기간 타이브레이크) 유닛 테스트.
- 프론트/Electron 쪽은 기존 관례대로 수동 검증.

## 열린 질문

- 커밋 시점 규칙 실행을 정확히 어느 기존 코드 지점(로컬 git 신규 커밋 감지 vs GitHub 동기화)에 걸지는 구현 계획 단계에서 실제 코드를 보고 정한다.
- 규칙 패턴의 오탐률은 실사용하면서 튜닝이 필요할 것 — v1은 "믿을 만한 조언자"가 아니라 "가끔 틀릴 수 있는 체크리스트"로 포지셔닝한다.
